### Jev配置実行の不具合修正

#### 原因

- APIの候補IDは回転・列・着地行（`r{rotation}-x{x}-y{y}`）を持っていたが、クライアントが`x`と回転だけを保存していた。
- 凹凸や棚ができると、同じ列・回転に複数の着地行が存在する。Jevが下段の候補を選んでも、クライアントは上段へハードドロップしていた。
- Jevの評価中にピースが固定してPauseへ入ると、再開時に次ピースの評価を起動しない経路もあった。

#### 変更

- Jevの目標に着地行`y`を含め、候補の`x` / `y` / `rotation`を一致させてからハードドロップするよう修正。
- 操作経路探索に`softDrop`を追加し、棚の横から下へ回り込む合法配置を再現できるようにした。
- Pause中に切り替わった未評価ピースを、Resume時に評価するようにした。

#### 確認

- `board[16][4]`と`board[16][5]`にブロックを置いた空盤面で、Oピースの`r0-x4-y14`と`r0-x4-y18`を列挙し、下段`y=18`までの操作経路をAPIなしで再現。
- `npm run lint`、`npx tsc --noEmit`に成功。

#### 原因

- 前回のハードドロップ変更で、低確信度のJev手もそのまま実行対象になっていた。確率は着地保証ではないため、盤面が危険な中盤以降にモデルの誤った戦術を確定する可能性が残っていた。
- Gateway要求が失敗したとき、要求時ピースIDを確認せず現在のアクティブピースへフォールバックを割り当てていた。重力で次のピースへ進んだ後に古い失敗が到着すると、新ピースのJev評価をスキップしていた。
- ソフトドロップの事前確認は入力直後の静止盤面だけで、直後の重力tickによる到達不能を見ていなかった。

#### 変更

- 70%未満または未取得の確率を持つモデル目標は確定せず、現在ピースから選ぶ決定的な安全合法手へ切り替える。救済手は`fallback`として確率を引き継がず、HUDでも分離して表示する。
- セッション内リクエスト世代と盤面リビジョンを追加し、ピースID・種類・盤面・NEXT・HOLD・保留おじゃま・REN/B2Bが変わった応答を破棄して再評価する。古い失敗の救済を新ピースへ適用しない。
- HOLD後の交換ピースを候補の種類と照合し、不一致なら現在ピースの合法手へ再計画する。
- ソフトドロップ後に32msの重力tickを先読みし、目標への経路が残る場合だけ入力を適用する。

#### 確認

- `npm run lint`、`npx tsc --noEmit`、`npm run build -- --webpack`に成功。
- 実ブラウザーで短時間のGateway対戦を開始し、応答待ち中もJevがP01からP21まで進行して試合が停止しないことを確認した。

#### 未確認

- 実Gatewayを使った長時間対戦で、古い失敗応答が新ピースへ適用されないことを連続観測する確認、および低確信度手が実際に`fallback`へ切り替わる長時間の実モデルE2Eは未確認。

### 2026-09-20（DiaのGateway待ち対策）

#### 原因

- DiaなどのブラウザーでGateway要求が長時間保留されると、Jevの初回評価が`thinking`のまま残り、画面上はゲームを開始できないように見える状態が続いていた。

#### 変更

- JevのGateway要求へ8秒のクライアントタイムアウトを追加した。タイムアウト時はAbortして、要求時ピースを検証したうえで安全なローカル合法手へ切り替える。
- `Reset`による通常のAbortはフォールバック扱いにせず、タイムアウトだけを救済処理へ渡す。

#### 確認

- `npm run lint`、`npx tsc --noEmit`、`npm run build -- --webpack`に成功。
- 開発サーバーを`0.0.0.0:3010`で起動し、`http://127.0.0.1:3010/`と`http://localhost:3010/`が200を返すことを確認。
- `/api/tetris/choose`の不正入力が400で返り、サーバーが応答可能なことを確認。

#### 未確認

- Dia本体からの8秒タイムアウト発火は、この環境からDiaを直接操作できないため未確認。
