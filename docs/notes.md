# 調査・実装上の判断

## Jev

- Jevの呼び出しは`src/lib/jev-provider.ts`へ集約し、TypeSafe公式、Vercel AI Gateway、OpenRouter、Cloudflare AI Gateway / Workers AIを環境変数で選べる。`JEV_PROVIDER=auto`は設定済みのTypeSafe、Vercel、OpenRouter、Cloudflareの順に解決する。
- TypeSafeとVercelはAI SDKのEvaluation API、OpenRouterはDecisions API、Cloudflareは`/ai/run` REST APIを使い、どの経路でも`answers`・`model`・token usageを同じ内部形式へ正規化する。
- Vercelの現行Evaluation API型にないconfidenceをUIで捏造しない。確率が返らない場合は`—`で表示する。
- 判断理由の自由文は生成しない。コード側で合法手を作り、回答はChoiceで選んだ配置IDに限定する。
- プロバイダの有料枠・認証・レート制限・通信エラーは画面に表示し、自動で別の請求先へ切り替えない。評価に失敗した場合はゲーム側だけが決定的なローカル合法手へ切り替える。

## Tetrisと対戦

- 7-bag、SRS回転キック、レベル別重力、500msロック猶予、最大15回の接地猶予リセットを採用した。ロック時間とレベル曲線はゲームタイトルで異なるため、実装値を明記する。
- 7-bagは`makeSevenBag`で7種類を1個ずつシャッフルし、キューが空になった時だけ次のbagを生成する。bag境界で同じ種類が2回続くことはあるが、3回連続にはならない。
- ゲームオーバーはスポーン位置の重なりを`spawn-blocked`、表示範囲より上だけでロックする状態を`lock-out`、おじゃま挿入で上端から押し出す状態を`garbage-overflow`として記録する。勝敗判定はこの`ArenaState.gameOver`を両盤面へ適用する。
- 各盤面のレベルはその盤面の消去ライン数から決める。ユーザー操作とJevの判断待ちの間も、それぞれの重力を進める。
- 攻撃は`guideline-battle-v1`として明示する1対1ルール。通常1/2/3/4ライン=0/1/2/4、フルTスピン1/2/3ライン=2/4/6、ミニTスピン1/2ライン=1/2、RENは`floor(combo / 2)`（2回目+1、4回目+2）、B2Bは+1、Perfect Clearは+10とする。任天堂の公開解説は対戦概念と一部の例を示すが、全タイトル共通の完全な数値表ではないため、数値はこのアプリの採用値として扱う。
- 受信側の保留おじゃまは消去ラインと攻撃力で相殺し、残りを次の固定時に下から挿入する。99人戦のバッジやターゲット補正は含めない。
- 攻撃時は`battleEvent`のIDで画面全体の揺れ・フラッシュを一度だけ発火し、勝敗時は盤面を覆わない試合バーへ結果を表示する。`prefers-reduced-motion`では揺れを停止する。
- 選択したJevプロバイダは通常Jevの各ピースに1回だけ呼び出す。要求中に盤面や相手公開盤面のリビジョンが変わった場合だけ、古い応答を捨てて同じピースを再評価する。要求は8秒で打ち切り、安全なローカル手へ切り替えるため、Diaなどでプロバイダ通信が保留されても人間側の対戦を止めない。課金を伴うため、ユーザーが開始した場合にだけ評価する。`Reset`は現在のリクエストをabortする。テスト用の固定応答モードは最終コードから削除する。
- Jevの判断コンテキストは、同じ`ArenaState`からNEXT 5個、HOLD、保留おじゃま、進行状況、重力・ロック猶予を生成する。接地していない間の`lockRemainingMs`は`null`として、ロック時計が動いていないことを明示する。
- Jevへは相手の公開盤面・NEXT・HOLD・保留おじゃま・REN/B2B・穴数・最高高度も送る。HOLD候補を現ピース候補と同じ原子的なChoiceへ含め、同じプロバイダ評価内でaction/posture/riskを並列に判断する。posture/riskはUIへ表示するが、actionを上書きしない。
- 候補には消去ライン内のおじゃまセル数、保留おじゃまの相殺量、相手へ残る送信量も含める。受信穴を掘る手と安定した攻撃手をJevが同じ表で比較できるようにする。
- Jevプロバイダ評価に失敗した場合は、試合を止めずに現在の合法配置を生存率・消去・攻撃・おじゃま相殺で順位付けし、最上位へ決定的にフォールバックする。フォールバックはモデルの判断として記録せず、画面に`FALLBACK`と表示する。モデル目標を確定する確信度ゲートは70%とし、ハードドロップ自体は確定済み目標の現在着地チェックで決める。応答後にモデルの目標が重力で到達不能になった場合も同じ合法手再計画を行う。
- 旧Decision Labはメインアプリから分離し、ローカルの`../jev-decision-lab`リポジトリへ退避した。jevtetrisの公開リポジトリには含めない。

## 2026-09-20 中央積みの自己診断

- 盤面文字列だけでは中央4列の危険度をJevが毎回安定して読み取れない可能性があるため、`boardProfile`として列ごとの高さ・最上段行・穴数・中央積みリスク・推奨退避方向を明示する。
- `centerStackRisk`は中央4列が高い、左右の高さとの差が大きい、中央の穴が増えた場合に上がる。これは強制分岐ではなく、Jevが左右への退避・おじゃま掘り・安定手を比較するための自己診断入力とする。

## 2026-09-20 ソフトドロップの実行制御

- ↓の連打はJevのChoiceではなくクライアントの経路探索が生成する。モデルの確率が70%未満または未取得なら、目標を確定せず、現在のピースから決定的な安全合法手へ切り替える。確率を理由に待機して重力へ任せることもしない。
- 信頼したJev手または安全な救済手は、列・回転・着地行・回転履歴が一致したときだけハードドロップする。ソフトドロップは棚の下へ回り込む中間操作に限定し、1行適用した後の次の重力tickまで先読みして、同じ目標へ到達できる場合だけ続行する。
- 同じ姿勢の通常配置と回転経路を候補統合する際は、Tスピンへ変わる場合だけ回転履歴を優先する。通常配置を不要な回転経路へ置き換えない。

## 2026-09-20（Jev応答の世代管理と低確信度救済）

- Gateway要求へセッション内のリクエスト世代、要求時のピースID・種類、盤面・NEXT・HOLD・おじゃま・REN/B2Bのリビジョンを紐付けた。応答時のリビジョンが変わっていれば、古いChoiceやエラーを適用せず、同じピースを再評価する。
- 失敗した古い要求のフォールバックを、その後スポーンした新しいピースへ割り当てないようにした。成功・失敗のどちらも要求時ピースと現ピースを照合する。
- 低確信度のJev選択、到達不能な選択、HOLD後の種類不一致は、Jevの確率を引き継がず、`fallback`として記録した安全な合法手へ切り替える。HUDではモデルの選択と救済手を分けて表示する。

## 確認範囲と未確認

- デスクトップと390×844のブラウザー画面を確認した。開始、ユーザーの横移動・回転、Jev応答待ち中の1行落下を確認した。
- Gatewayを呼ばない一時モックとテスト盤面で、1ライン消去の点滅と残ブロックの落下要素をブラウザー確認した。固定応答・テスト盤面の分岐は最終コードから削除した。
- 盤面ロジックは7-bag、合法配置、レベル別重力、固定猶予、ライン消去、攻撃・REN、おじゃま挿入をNode.jsで確認する。
- 最終サーバーに不正な空ゲーム状態を送り、`400 INVALID_GAME_STATE`でGateway評価前に止まることを確認した。認証環境変数の存在までの確認であり、実モデルの認証・評価確認ではない。
- 今回の確認では実Gateway評価を短時間実行し、応答待ち中もJev盤面とピース進行が止まらないことを確認した。低確信度手が実際に`fallback`へ切り替わる長時間の実モデルE2Eと、追加再評価の課金・レート制限への影響は未確認。
- 重力曲線、ロック猶予、対戦攻撃はタイトル固有であり、このデモは任天堂の公開仕様を参照した`guideline-battle-v1`の1対1。99人対戦の標的選択・バッジ・攻撃補正は対象外。
